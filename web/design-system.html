Devis design system

The Heads-Up Console

Smoked glass panes hover over a lit ink field, and light marks what the machine is attending to: the open pull request, the focused control, a running pipeline. Every specimen on this page is built from the app's own stylesheet (web/style.css) and the markup the app renders, so it cannot drift. DESIGN.md is the written spec; this page is the rendered one.

One Light
Only cyan glows. If two unrelated things on screen are cyan, one of them is wrong.
Color Is Evidence
Hue appears only where it carries meaning: a vote, a status, a severity or a diff line.
Readout
IDs, branches, build numbers, durations and zoom levels are set in Cascadia Mono with tabular figures.
Glass Budget
Glass belongs to panes, heads, floats, dialogs and pipeline blocks. Everything inside a pane is a tint.
Near-Opaque Float
Anything that opens over content is at least 84% opaque, so code and diagrams never ghost through.
Fallback
Under reduced transparency the glass turns solid; in forced colors, system colors take over.

Composition

The title bar sits on the field. Below it the queue pane and the reading pane float with an 8px gutter. The reading pane keeps a frosted head above one scrolling column.

Patterns

How the pieces behave together. DESIGN.md is the source; this chapter is the quick read.

Queue model

Two tabs, remembered across launches. My feed puts each pull request that concerns you in exactly one lane. All lists every pull request in scope, grouped by repository and folded by default.

Lane assignment, checked in this order

  1. Your pull requests. You authored it. Pull requests where a reviewer is waiting on you or rejected float to the top; drafts fold into a closed "N drafts" group.
  2. You've weighed in. You voted or commented.
  3. Needs your review. It is assigned to you.
  4. Copilot reviewed. A Copilot review is queued, running, done or failed. Reviews in progress lead.

Lanes display as Needs your review, Copilot reviewed, You've weighed in, Your pull requests. Inside a lane, drafts sink below published and the newest leads.

Hide moves selected rows out of My feed; they stay in All. A footer counts them and opens a "Hidden from your feed" lane with Restore. Queuing a Copilot review restores a pull request automatically.

Search (Ctrl+F) filters both tabs. Terms are ANDed and case-insensitive.

Accessibility

Glass is decoration; nothing depends on it. Every rule below holds with blur off, transparency reduced and forced colors on.

RuleHow
Focus is always visibleA 2px --focus (pale cyan) outline at a 1px offset, inset on full-width rows and tabs. Never removed.
Icon-only controls are namedEvery icon button carries an aria-label; its tooltip adds the shortcut.
Navigation states are exposedSection tabs are buttons in a labelled nav with aria-current; folds use aria-expanded, toggles use aria-pressed.
Status is written outBlocks, run chips, badges and the inspector always say the status. Tone alone never carries meaning.
Progress is announcedA visually hidden live region announces chain run progress.
Forced colorsBlur, field effects and pane shadows drop; selection bars, tab underlines and the selected block use Highlight; status dots keep their colors.
Reduced transparencyEvery glass tier turns opaque and blur is off.
Reduced motionFlowing arrows freeze and the running bar becomes a static full-width line.

Do's and don'ts

Verbatim from DESIGN.md.

Do

  • Do use the tokens; add a token before adding a raw value.
  • Do keep glass to panes, heads, floats, dialogs and pipeline blocks, and keep everything inside a pane as tints.
  • Do keep one emissive cyan per view, and let severity and diff colors carry meaning.
  • Do set IDs, branches, build numbers and other readouts in Cascadia Mono.
  • Do check new components in web/design-system.html, at 1440px and below 1100px, and with reduced transparency on.

Don't

  • Don't make rows, cards, badges or fields their own glass; nested blur muddies the content and costs frames.
  • Don't let anything other than cyan glow, and don't glow decoratively: glow means selection, focus, running or the primary command.
  • Don't drop a float, head or dialog below 84% opacity; code and diagrams must never ghost through.
  • Don't add light-theme surfaces; the shell forces dark so the glass always reads as smoked.
  • Don't use colored side stripes on blocks, rows or cards.
  • Don't use emoji as icons; use icon() from web/src/icons.ts.
  • Don't put a <button> on the page without a base class.
  • Don't show raw HTML or Markdown in previews.

Every specimen on this page is styled by the app's own style.css and icons, so it can't drift from the app. Change DESIGN.md first, then the CSS, then check the change here at 1440px and below 1100px.
